## How the rendering was taken

`capture-readme.mjs` (outside the repository, in `katalis-dev/`) does what the task asks:

1. it sends each README to `POST https://api.github.com/markdown` with `mode: gfm` and no token, so the HTML is the
   one GitHub produces;
2. it rewrites every `src="docs/...` and `srcset="docs/...` of that HTML to the absolute `file:` URL of the file in
   the repository, so the images of the capture are the real images of the README;
3. it writes the HTML outside the repository and opens it with Playwright at 1280 × 1300 and 400 × 1500, in
   `prefers-color-scheme: light` and `prefers-color-scheme: dark`;
4. it takes one full-page capture of `README.md` at 1280 in dark.

## The defect this step found

The first capture showed the badges and the language switch as **literal markdown**
(`[![License: Apache-2.0](...)`), because they were inside a block of raw HTML:

```html
<p align="center">
  [![License: Apache-2.0](https://img.shields.io/badge/...)](LICENSE)
  ...
</p>
```

**GitHub does not parse markdown inside a block of raw HTML**, so a reader of the repository would have seen the
source of the badges instead of the badges. The same happened with the language switch. The fix, in commit `3cdd11a`,
takes the seven badges and the two language links out of the `<p>` and leaves them as plain markdown. The test did not
catch it because it reads the file, and the file was valid markdown; the rendered HTML is what caught it, which is why
this step exists.

The second defect was in the capture tool itself: the `<source>` of every `<picture>` carries its path in `srcset`, and
the first version only rewrote `src`, so the dark captures showed the alt text of every image. The captures of this
report are the ones with both attributes rewritten.
