What each scenario of the panel proves, in the order of the spec:

| Scenario | What the run does |
|---|---|
| A first visit and a switch | `/admin` opens in English with `lang="en"` on `<html>`, the wrong password shows its message, the right one opens the panel, and the switch writes the cookie: the page reloads in Spanish with `lang="es"` and the button of the form reads `Guardar el negocio` |

| Locked after five failures | five failures of `198.51.100.240` and the sixth attempt, which carries the right password, answers `429` |
| Every admin route checks the session | the curl run of task 6.1 and the twelve handlers of `tests/admin-routes.test.ts` |
| Values never leave the server | the setup page lists `ADMIN_PASSWORD`, `EMBEDDINGS_PROVIDER` and `ALLOWED_ORIGINS` and its HTML does not contain the password of the run |
| An SVG or a renamed file | the SVG of `logo.svg` is refused with the message of the rule |
| A forbidden topic | the prompt test of `tests/admin-business.test.ts`; the run saves the topic in the form |
| Upload, list, delete | `cafe-la-horquilla.md` is uploaded, listed with its four passages and deleted |
| Delete all | a real question is asked over `/api/ask`, the panel lists it as answered, and the delete leaves the table empty |
