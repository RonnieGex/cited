is the sample one, the embeddings are `createFakeEmbeddings()` and the chat provider is `fake`.

## The command and its output

`npx -y -p node@24` cannot run in this sandbox: npm cannot write its cache outside the workspace and cannot spawn a
child with piped stdio. The loop runs the same Node that command resolves, taken from its own cache, which is
`v24.21.0`:

```
$ <npx cache>\node_modules\node\bin\node.exe -v
v24.21.0
```

Vite probes `net use` once per process through `child_process.exec` (a pipe), and the sandbox refuses that spawn with
`EPERM` before any test starts. The command of the loop therefore adds `--pool=threads` and a preload that answers that
one probe without a process, because this machine has no mapped network drive. It is a property of this sandbox and not
of the repository: on a normal machine the documented command is
`npx -y -p node@24 node node_modules/vitest/vitest.mjs run`.

```
$ node node_modules/vitest/vitest.mjs run --pool=threads tests/mcp-protocol.test.ts tests/mcp-tools.test.ts tests/mcp-route.test.ts
```
