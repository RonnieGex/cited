## What the two tests assert

`tests/home.test.tsx` (Vitest with jsdom and React Testing Library) renders the page component and asserts that there
is one first level heading with the product name and one `main` region.

`e2e/home.spec.ts` (Playwright) requests `GET /` against the built application on port 3100, asserts the status 200
and asserts the same heading in the served HTML.

## Honesty about the order

The page of this change is one line long and it was written before its test, because the skeleton has to exist for
Vitest to have anything to render. The red runs below are real and they prove the test is not vacuous, and they are
not presented as a strict test-first cycle that did not happen.

## Red run 1: the test found a real defect in the configuration

```
npm test
  -> ❯ home page (2)
  ->   × renders a single main region 20ms
  -> Test Files  1 failed (1)
  ->      Tests  1 failed | 1 passed (2)
  -> exit 1

FAIL  tests/home.test.tsx > home page > renders a single main region
AssertionError: expected [ <main><h1></h1></main>, …(1) ] to have a length of 1 but got 2
```

Two `main` regions after one `render`: React Testing Library only registers its automatic cleanup when the test
globals exist. The configuration was missing `globals: true`. It was added to `vitest.config.mts` and the suite went
green. The failing test found a real defect, not a test artifact.
