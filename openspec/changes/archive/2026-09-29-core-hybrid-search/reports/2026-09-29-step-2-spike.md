## 2.1 The spike test

creates a table with an `F32_BLOB(8)` column, inserts vectors, creates a vector index, runs `vector_top_k`, orders by
`vector_distance_cos`, creates an FTS5 virtual table, runs a `MATCH` query and reads `bm25`. It deletes its temporary
directory at the end. The file carries a memory ceiling assertion so the spike also reports the resident memory of the
client, which the RAM task of step 9 needs.

## What the spike found, including what surprised it

1. **Native vectors work.** `F32_BLOB(8)` is accepted as a column type, `vector(?)` binds a `Float32Array` from the
   Node client, `vector_extract` returns the stored values, `libsql_vector_idx(embedding)` creates the index and
   `vector_top_k('passages_embedding', vector(?), k)` returns the nearest keys in order.
2. **`vector_top_k` returns the keys only.** `SELECT id FROM vector_top_k(...)` works and `SELECT *` returns `id`, but
   `v.distance` does not exist as a column (`SQLITE_ERROR: no such column: distance`). The distance is measured in the
   query with `vector_distance_cos` over the joined table, which is what the store does. This is recorded here because
   it decides the SQL of the search module.
3. **`vector_distance_cos` also works without the index**, so the fallback path of the design decision 1 (order by
   distance when the index is not available) is real and testable.
4. **FTS5 works, with the standalone form.** `CREATE VIRTUAL TABLE … USING fts5(text)` answers `MATCH` and `bm25`.
   The external-content form with `content='passages', content_rowid='id'` is **not** used: with it, the same inserts
   produced `count(*) = 0` in the shadow table and the `MATCH` query returned nothing, because an external-content
   table is fed by triggers, which the spike does not create. The store therefore uses a standalone FTS5 table and
   keeps it in sync explicitly. This is a real finding of the spike and it is one of the reasons the spike exists.
5. **`bm25` ranks lower-is-better**: `ORDER BY score` with ascending values puts the best match first (`-0.000001`),
   which is the order the keyword ranking of the search module uses.
