## Note on the Linux container

The first attempt mounted the clean clone with the `node_modules` that `npm ci` had installed on Windows, and Vitest
could not start inside the container:

```
Error: Cannot find native binding. npm has a bug related to optional dependencies …
  cause: Error: Cannot find module '@rolldown/binding-wasm32-wasi'
```

The Linux run is therefore made with the sources of a clean clone copied inside the container and with `npm ci` run
there, which is what gives the container the native binding of its own platform:

```
docker run --rm -v <clean clone>:/src:ro node:24 sh -lc "mkdir -p /work && tar -C /src --exclude=./node_modules --exclude=./.next -cf - . | tar -C /work -xf - && cd /work && npm ci --no-audit --no-fund > /dev/null 2>&1 && node --version && node node_modules/vitest/vitest.mjs run"
```

The container never touched the store of the worktree and no secret was in its environment.
