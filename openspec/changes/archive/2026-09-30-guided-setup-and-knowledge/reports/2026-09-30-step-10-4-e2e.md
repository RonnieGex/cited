## The first run of the suite, and why it was not green

The first `CI=1 npm run test:e2e` of this task, in a clean clone of `9e4b231`, ended:

```
  1 failed
    [setup-es] › e2e\setup-es.spec.ts:129:5 › de cero a una respuesta, en español, cronometrado
  1 flaky
    [setup-es] › e2e\setup-es.spec.ts:109:5 › la primera visita en español muestra el saludo y los cuatro pasos
  1 did not run
  82 passed (2.1m)
```

Two defects of the new spec, and no defect of the product:

1. The case looked for the citation control by its English name (`/Citation 1/`). The accessible name comes from
   `citationLabel` of the panel, which is "Cita {n}" in Spanish, so the control was never found. It now reads
   `spanish.citationLabel.replace("{n}", "1")`.
2. In CI Playwright retries a failed case, and the group of the Spanish spec is serial over one store: the retry of the
   first case ran over a store the walk had already walked, and failed on the words of the assistant that is not ready.
   The group is now `{ mode: "serial", retries: 0 }`, with the reason written over it: a retry would re-enter a store
   another case of the group already walked.

Both are in `ecd054d`, and the run above is the one after them.

## Note on the node of the browser suite

The clone of this task ran with the node of the machine, `v24.11.0`, because `playwright.config.ts` starts the servers
with `npm start` and npm runs with the node next to it. The suites of task 10.3, which the contract pins to Node 24.15
or newer, ran with `v24.21.0`. The browser suite of the round before this one ran the same way, with the node of the
machine, and nothing of this amendment changed that.
