## Decisions taken by the implementer

The fifteen decisions are written under "Decisions taken by the implementer" of
`openspec/changes/mcp-server/design.md`, and they are copied to the delivery. In short, the ones a reviewer should
look at first:

1. No session, no `Mcp-Session-Id`, no `DELETE`: the transport is stateless.
2. The token is read on every request; without it the route answers `404` for every method, with no body.
3. The order of the refusals is off (`404`), origin (`403`), token (`401`), version header (`400`).
4. "The site's own origin" is the `Host` of the request; the scheme is not compared, because TLS ends in front.
5. `MCP_RATE_LIMIT_PER_HOUR` counts tool calls per token in the memory of the process; only `tools/call` consumes it.
6. `askQuestion()` gains `quota: "ip" | "external"`, so the MCP tool replaces the per-address limit with the per-token
   one; the daily cap of model calls and the retention are untouched.
7. The MCP channel is not stored: no column, no table and no migration.
8. An unknown tool is `-32602`; `-32601` is for a method the server does not implement.
9. `cited_search` falls back to the keyword mode when the installation has no embeddings provider.
10. Both tools answer `structuredContent` and the numbered text of the spec.
11. The excerpt of a passage is its text, as the citation of an answer carries it.
12. `MAX_QUESTION_CHARS` applies to both tools; `limit` outside 1..8 is `-32602`.
13. Every sentence passes through `publicMessage()`, with the fallback of its error code.
14. Two tools in one table; no registry until a third exists.
15. The constant-time comparison lives in `lib/guards/bearer.ts`, re-exported by `lib/voice/secret.ts`.

## Issues

### BROKEN

- **`npm audit --audit-level=high` fails on this branch and on the base `f644f85`.** The measured result is 7 high
  (`next` 16.3.6, `@next/eslint-plugin-next`, `eslint-config-next`, `braces`, `fast-glob`, `micromatch`,
  `source-map-js`), 3 moderate and 0 critical. `package.json` and `package-lock.json` are byte-identical to the base,
  so this change adds no dependency and did not produce the finding; the `audit` job of the pipeline is red on `main`
  today. The gate names the situation in its own line and treats it as satisfied for this change. Fixing it means
  upgrading `next`, which is a decision of Fable and not of this contract.

### RISK

- **The per-token limit lives in the memory of the process.** An installation that runs several Node processes counts
  each one apart until it restarts, so the effective ceiling of `MCP_RATE_LIMIT_PER_HOUR` can be that many times the
  value. It is a guard of the balance of the owner, not a distributed quota; a store-backed counter would need a
  migration (decision 5 of `design.md`).
- **The gate adapts itself to this Windows sandbox.** A child process with piped stdio is refused here, and Next.js
  forks its type checker and its page workers, so `scripts/gate-mcp.mjs` writes those pipes to temporary files and, for
  the production build only, sends the workers of Next.js to the thread pool. The adaptation is installed only when the
  gate measures the refusal, so a machine that allows pipes runs every command untouched; a reviewer should read the
  two shims of the gate before trusting a `GATE: GREEN` from another platform.
- **The suite of this machine ends with the access violation of the platform (`0xC0000005`) in about one of twenty
  processes of the threads pool**, after a clean summary, and occasionally in the middle of a chunk. The gate runs the
  94 files in chunks of five and repeats a chunk whose process ends that way, up to three attempts; the lines of the
  gate name every repetition. No test failed in any attempt (`1129 cases passed`), and the whole suite passes through
  the `forks` pool of the pipeline on a machine that allows pipes.

### NOT DONE

- **The configuration of every client is documented, not verified.** DeepSeek Harness, Claude Code, Codex and Cursor
  are written in `docs/mcp.md` as their own documentation describes them, and neither README claims one of them works.
  Fable connects each client and marks as verified only the ones that work.
- **`cited_ask` was never exercised against a real chat provider in this round.** The gate runs without a provider by
  design, the manual verification too, and the unit tests use the deterministic double of `ai/test`; the provider path
  is the one `/api/ask` already runs and `tests/answer.test.ts` covers for the pipeline. A live provider needs a key
  that the contract keeps out of this round.
- **No end-to-end (Playwright) run**: the change has no interface (step 8).

### UNKNOWN

- **A client that insists on the revision `2026-07-28` of the protocol** (the one the DeepSeek Harness client prefers
  when the server offers it) receives `2025-06-18` from this endpoint, because the contract fixes the two revisions it
  negotiates. Whether the client of DeepSeek Harness accepts that answer was not verified here; the specification says
  a client that does not support the version of the server's response should disconnect.
- **The behaviour of the three clients with a real token** (what they show when a call fails, how they paginate the two
  tools, whether they cache the list): Fable's review decides.
