## Where it ran, and why not in this worktree

Before each run: `netstat -ano | findstr ":3100 :3210 :3211 :3212 :3213 :3214 :3215 :3216"` printed nothing, so no other lane was on the ports of the suite.

The first run was in the worktree `community-ui` itself and it showed a fact about this checkout: it holds an ignored `.env.local` (I never opened it, as the rules ask). Next reads
`.env.local` for `next start` too, so the two servers of the suite that must start with no provider (`keys` and `affiliate`) came up with a chat provider "Set by the server" and
`e2e/providers.spec.ts` and `e2e/affiliate.spec.ts` failed for that reason. The run is therefore made in a plain clone of the branch, the way CI checks it out and the way the earlier
rounds ran (`community-e2e`): `git clone --branch feature/brand-identity-ui <worktree> <temp>/c14c-e2e`, `npm ci`, then the command above. The unit tests do not load `.env.local` (vitest
reads none of it into the environment) and the curl of 10.4 passed its own environment explicitly.
