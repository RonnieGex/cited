## What the requests prove

- **Without the session the route answers 401 and calls nothing:** the first request never reached the double, whose
  log carries three lines and not four.
- **A good key is tested before it is saved:** the test answers the model and the latency, and the save repeats the
  test and answers the last four characters.
- **A rejected key is a word and not a text of the provider:** `rejected_key`, with no line of the 401 of the double.
- **The key never comes back:** the state of the panel, the page of AI and keys and every `/api/admin/*` response
  carry the last four characters, no key and no `v1:` of the ciphertext.
- **The store holds the ciphertext and never the key:** the row of `provider_settings` carries 81 characters that
  start with `v1:` and that do not contain the key.
- **The encryption of the server is used:** the same run that wrote `ENCRYPTION_KEY` in the environment read the row
  back, and the API says `"encryption": true`.

## The double, in full

```js
import { createServer } from "node:http";

const port = Number(process.argv[2] ?? 3216);
const good = process.argv[3] ?? "sk-buena-0000000000007788";

const server = createServer((request, response) => {
  const chunks = [];

  request.on("data", (chunk) => chunks.push(chunk));
  request.on("end", () => {
    const authorization = request.headers.authorization ?? "";

    response.setHeader("content-type", "application/json");
    console.log(`${request.method} ${request.url} ${authorization === `Bearer ${good}` ? "200" : "401"}`);

    if (authorization === `Bearer ${good}`) {
      response.writeHead(200);
      response.end(JSON.stringify({
        id: "chatcmpl-doble", object: "chat.completion", created: 1_700_000_000, model: "gpt-4o-mini",
        choices: [{ index: 0, message: { role: "assistant", content: "ok" }, finish_reason: "stop" }],
      }));
      return;
    }

    response.writeHead(401);
    response.end(JSON.stringify({
      error: { message: `Incorrect API key provided: ${authorization}`, type: "invalid_request_error", code: "invalid_api_key" },
    }));
  });
});

server.listen(port, "127.0.0.1", () => {
  console.log(`the double listens on http://127.0.0.1:${port}`);
});
```
