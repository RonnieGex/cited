## The defect this step found in the branch, and its repair

While the checkboxes of `tasks.md` were being marked, this session edited that file with a PowerShell round trip
(`Get-Content -Raw` and `[IO.File]::WriteAllText`) that read the UTF-8 of the file with the default encoding of
Windows PowerShell. Every em dash of the contract became mojibake, and the corruption was committed in the first
commits of the branch without anybody noticing: the suite does not read that file and OpenSpec does not check its
bytes.

The step found it while printing the file, and the repair is exact: the contract was restored from `71f08f0`
(`git checkout 71f08f0 -- openspec/changes/provider-keys-in-panel/tasks.md`) and the marks were applied again reading
and writing UTF-8 explicitly. Measured:

```
$ git diff 71f08f0 -- openspec/changes/provider-keys-in-panel/tasks.md | Select-String '^[+-]- \['
-- [ ] 0.1 Work on `feature/provider-keys-in-panel`, ... `npm ci` —
+- [x] 0.1 Work on `feature/provider-keys-in-panel`, ... `npm ci` —
... sixteen lines, the same line with the box marked and nothing else
```

The diff against the contract is now exactly the sixteen checkboxes, and the text of every task is byte for byte the
one Fable wrote. A scan of the tracked text files for the signature of the double encoding, the two characters that a
UTF-8 accent becomes when the same bytes are read as Latin-1, finds nothing.
