## Why the fixture

The Major of `katalis-dev/tasks/revision-passage-display-polish-c.md` is that the branch removed the cut of a block at a
blank line from `lib/ingest/chunk.ts`, so every section without a list that spans more than one passage is cut
differently from `main`: a passage that is only the heading, and cuts in the middle of a sentence. The sample corpus
(`samples/`) does not move, so no test could see it. Decision 19 fixes that with a golden fixture of the chunker over
the documents of the repository itself, and the test that requires it goes before the fix.

## The command that wrote the fixture

`scripts/chunk-golden.mts` writes the passages that one build of `lib/ingest/chunk.ts` returns for every Markdown and
text file of `docs/` and `samples/`. The fixture was written once, from the chunker of `86b250f`, with these two
commands in `<worktree>` (Node `v24.21.0`, the one of `npx -y -p node@24`):

```powershell
$source = (git -C <worktree> show 86b250f:lib/ingest/chunk.ts) -join "`n"
[System.IO.File]::WriteAllText("<scratch>\chunk-86b250f.ts", $source + "`n", (New-Object System.Text.UTF8Encoding($false)))

<worktree> > npx -y -p node@24 node scripts/chunk-golden.mts <scratch>\chunk-86b250f.ts tests/fixtures/chunker-golden.json "86b250f:lib/ingest/chunk.ts"
23 files, 345 passages
```

The extraction writes UTF-8 without a BOM: PowerShell's `>` re-encodes the output of `git show` as UTF-16 and Node
refuses to read TypeScript from it. The first argument of the generator is the implementation to measure and the third
one is the label the fixture carries, `86b250f:lib/ingest/chunk.ts`; the label holds no path of this machine. Whatever
build is passed, the script reads the same 23 files from the working tree.

## The fixture

`tests/fixtures/chunker-golden.json` (191,698 bytes):

| | |
|---|---|
| `label` | `86b250f:lib/ingest/chunk.ts` |
| Files | 23 (19 Markdown of `docs/`, and the 4 of `samples/`: two Markdown and two text) |
| Passages | 345, each with its `heading` and its `text` |

`tests/chunk-golden.test.ts` has two cases:

- **"keeps every passage of every Markdown and text file of docs/ and samples/"** chunks every file the fixture names
  with the chunker of the branch and compares passage by passage, once the line break of a list join is read as a
  space (`text.replace(/\n/g, " ")`). It stops at the first difference and names the file, the position and the two
  texts.
- **"names every Markdown and text file of docs/ and samples/ in the fixture"** requires the fixture to name exactly
  the `.md` and `.txt` files the tree holds, so a new document cannot enter the repository without the fixture being
  written again.
