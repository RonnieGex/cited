## The E2E test that asserted the old payload

`e2e/voice.spec.ts` carried the assertion of the very answer this change corrects:

```js
test("the signed URL of the server names the missing variable and the browser never gets the key", ...)
  expect(seen).toContain("ELEVENLABS_API_KEY");
```

The test is now "the signed URL of the server answers a code and the browser never gets the key" and asserts the
opposite, which is the new rule of the public route:

```js
expect(seen).toContain("voice_unavailable");
expect(seen).not.toContain("ELEVENLABS_API_KEY");
expect(seen).not.toContain("xi-api-key");
expect(seen).not.toContain(sentinel);
```

`seen` is the body of the `503` of `/api/voice/signed-url`, the headers of every answer of `/api/voice/*` and the body
of every script the page fetched, so the test now proves that neither the code path nor the bundle of the browser
carries the name of the variable. The comment of `playwright.config.ts` that said "the signed URL route answers 503
naming the variable instead" was corrected to the code `voice_unavailable`: it is the sentence that explains why the
voice variables of the public server are set empty.

Both files travel in the commit of this report. No other spec of the suite changed: `e2e/affiliate.spec.ts` already
reads the answer of `/api/admin/voice` (with `allow: [503]`) and asserts that it carries no key, and that check is
unchanged and green.
